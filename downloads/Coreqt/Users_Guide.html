1. Overview & Prerequisites

Overview

CoreQT RM is an Eclipse/Capella plugin that extends the Capella MBSE workbench with advanced requirements management capabilities built on top of the Requirements Viewpoint (VP). It provides a traceability matrix engine for extracting, analyzing, and visualizing relationships between Capella model elements and their associated requirements, along with a role-based access control (RBAC) system that governs who can view, edit, or approve changes.

Features Summary

  • Automated Extraction — Scans the Capella model and Requirements VP to build a full traceability matrix linking system components to their requirements.
  • Interactive Matrix View — An SWT-based table view embedded in the Capella workbench for browsing and filtering requirement-to-element relationships.
  • Suspicion Engine — Detects potentially broken or stale requirement traces when the underlying model changes.

2. Installation & Quick Start

Installation

  1. Clone this repository into your Eclipse workspace.
  2. Import the project: File → Import → Existing Projects into Workspace.
  3. Set the Target Platform to your Capella installation (Window → Preferences → Plug-in Development → Target Platform).
  4. Build: Project → Clean → Build All.
  5. Run: Run → Run Configurations → Eclipse Application (pointing to your Capella product).

Quick Start — RBAC Setup

  1. Launch Capella with the plugin installed.
  2. A CoreQT Login dialog will appear. Enter your OS username.
  3. On first launch, create your initial admin user:
    • Right-click in the Project Explorer → Coreqt RM → Manage Users.
    • Add your username with role ADMIN.
    • Click Save Changes.
  4. Subsequent launches will enforce role-based permissions on all model modifications.

3. Capella Setup: Enabling Test Cases

Before you can trace Requirements to Test Cases, you must enable the native Kitalpha Requirements extension in your Capella Session.

Activating the Add-on in the .aird File

  1. Open your Capella project and double-click the .aird file to open the Session Editor.
  2. In the Session Editor, find the section labeled Viewpoint Manager.
  3. Look for the Viewpoint named Requirements (provided by Kitalpha).
  4. Right-click the Viewpoint and select Reference (or check the box to activate it).
  5. Save the .aird file. Your model is now ready to handle native Requirements and Test Cases.

Creating and Linking Test Cases

With the viewpoint active, you can now instantiate Test Cases in your Architecture (e.g., Logical Architecture or Physical Architecture). Test Cases can typically be created in Architecture Blank diagrams, such as the System Architecture Blank (SAB), Logical Architecture Blank (LAB), or Physical Architecture Blank (PAB).

Enabling Test Cases in Diagrams: If you don't see the "Test Case" element in your diagram palette on the right, you need to activate the Requirements layer for that specific diagram. Click anywhere on the white background of your open diagram, go to the Properties View at the bottom, select the Layers tab, and check the box for the "Requirements" or "Kitalpha" layer. The tools will then appear in the Palette!
  • Use the Capella Palette to drop a Test Case element onto your diagram or create it via the Model Explorer.
  • In the Semantic Browser or Properties View, you can manually link this Test Case to a System Component.
  • Note: The Traceability Matrix will automatically detect these links to warn you if a requirement has a component, but that component lacks a test case!

4. The Traceability Matrix

The Traceability Matrix is the core feature of the plugin, providing a bird's-eye view of your project's requirement coverage.

Extracting the Matrix

  1. In the Model Explorer, right-click on a Capella `.melodymodeller` file or a specific architecture layer (e.g., Physical Architecture).
  2. Select Coreqt RM > Extract Requirements Matrix.
  3. The Traceability Matrix view will open automatically at the bottom of your screen.

Interactive Traceability (Creating Links)

Unlike standard static matrices, the Coreqt RM Matrix is fully interactive:

  • Create a Link: Double-click any empty cell where a Requirement (Row) and a Component (Column) intersect. The plugin will automatically generate a native Capella Trace in the background and update the cell.
  • Remove a Link: Double-click a cell that currently contains a link (e.g., marked with ✅). The plugin will delete the trace from the Capella model safely.

Gap Analysis

At the bottom of the Traceability Matrix view, click the Gap Analysis tab. This tab lists all Requirements that currently have zero links to any system components. This is critical for ensuring 100% requirements coverage during reviews.

5. The Suspicion Engine

The Traceability Matrix includes a built-in "Suspicion Engine" that analyzes the health of your traces in real-time. It ensures that the critical chain: Requirement ➔ Component ➔ Test Case is fully intact.

Icon Meaning Action Required
✅ Healthy Link None. The Requirement is properly linked to the Component, and the Component is properly linked to a Test Case.
❌ Missing Test Case The Requirement is linked to a Component, but the Component has no Test Case assigned to it. You must create a Test Case for this component in Capella.
⚠️ Suspicious / Orphaned The Trace exists in the model, but one of the endpoints (the Requirement or the Component) has been deleted or corrupted. The link should be investigated or removed.
Tip: You can use the "Source Filter" and "Target Filter" dropdowns at the top of the matrix to quickly filter the view to only show "Missing Test Cases" (❌) or "Healthy Links" (✅).

6. Impact Analysis

When changing a system component or a requirement, it is crucial to understand what other parts of the system will be affected. The Impact Analysis feature generates a visual graph of all downstream trace links.

Running an Impact Analysis

  1. Right-click any model element (e.g., a Requirement, a Logical Component, or a Test Case) in the Model Explorer or inside a diagram.
  2. Select Coreqt RM > Analyze Impact.
  3. The system traverses the model's trace links up to a depth of 3 hops and computes all affected elements.

The Impact Graph View

If affected elements are found, the Impact Analysis Graph view will open.

  • Visual Representation: The selected root element is displayed on the left, branching out to all impacted elements on the right.
  • Trace Paths: Arrows between the nodes show exactly how one element affects another.
  • Detailed Reporting: The console will log exactly how many elements were found and affected.

7. Baselines & Version Control

Baselines allow you to take a "snapshot" of your requirements and matrix state at a specific point in time (e.g., before a major design review).

Creating a Baseline

  1. Right-click anywhere in your project and select Coreqt RM > Create Baseline.
  2. The system will generate a new folder named coreqt-baselines containing a .baseline file and a .coreqt manifest.

Comparing Baselines

You can compare two different baselines to see exactly what changed between them.

  1. Hold Ctrl (or Cmd on Mac) and select exactly two .baseline files in the Project Explorer.
  2. Right-click and choose one of the following:
    • Compare Baselines (Matrix): Opens a visual matrix showing added, removed, and unchanged links side-by-side.
    • Compare Baselines (Summary): Opens a text-based dialogue summarizing exactly how many links were added or deleted.

Compare with Live Model

If you want to see what has changed since your last snapshot: Right-click a single .baseline file and select Coreqt RM > Compare with Live Model (Matrix). This compares the saved baseline against your current, unsaved Capella model.

8. Version History

The Version History view provides a chronological ledger of all baselines created in your project.

  • Open it via Window > Show View > Other... > Coreqt RM > Coreqt Version History.
  • This view automatically scans your project for all .baseline files and displays them in a neat table, showing the Baseline ID, Author, and Timestamp.
  • This is highly useful for auditors to prove that requirements were tracked and versioned over the lifecycle of the project.

9. Role-Based Access Control (RBAC)

The CoreQT RM Plugin includes a Role-Based Access Control (RBAC) system that governs who can view, edit, or approve changes in the model. This ensures that only authorized personnel can modify critical system architecture or requirement traces.

  • Hierarchical Roles — Five privilege levels: READER → REVIEWER → REQUIREMENTS_ENGINEER → APPROVER → ADMIN.
  • Fine-Grained Write Protection — A pre-commit transaction listener intercepts all model modifications and enforces role-appropriate access:
    • General Capella elements (components, functions, etc.) → requires ADMIN.
    • Requirements VP elements (requirement names, relations) → requires REQUIREMENTS_ENGINEER or above.
  • Login Prompt — Startup dialog validates the user against a secure, encrypted user store.
  • AES-256 Encrypted User Store — User-role mappings are stored in a GCM-encrypted binary file (coreqt-users.dat) to prevent external tampering.
  • In-App User Management — Administrators can add, edit, and remove users through a built-in dialog (right-click menu → Coreqt RM → Manage Users).
  • Audit Logging — Every permission check (allowed or denied) is appended to an audit trail (coreqt-audit.log).
